# C4 Architecture Verification

Validate the accuracy and completeness of a hierarchical C4 architecture map.

## Prerequisites

Hierarchical C4 model must exist in `codemap/<system-id>/` folder (generated by `/viz/c4-map`).

First, identify the system and read all codemap files:

```bash
# Find the system folder
SYSTEM_ID=$(ls codemap/ | head -1)
echo "System ID: $SYSTEM_ID"

# List the hierarchy
find codemap -type f \( -name "*.md" -o -name "*.puml" \) | sort
```

Read the hierarchy:
- `codemap/README.md`
- `codemap/<system-id>/context.md` and `context.puml`
- `codemap/<system-id>/containers/<container-id>/container.md` and `container.puml`
- `codemap/<system-id>/containers/<container-id>/components/<component-id>/component.md` and `component.puml`
- `codemap/<system-id>/containers/<container-id>/components/<component-id>/code/classes.md` and `classes.puml`

## Instructions

Use the Task tool to spawn 4 parallel Explore subagents in a single message. Each subagent verifies a different aspect of the hierarchical C4 model.

### Subagent Invocations

**Subagent 1: Completeness Check**
```
Tool: Task
Parameters:
  subagent_type: "Explore"
  description: "Verify C4 completeness"
  prompt: |
    TASK: Verify COMPLETENESS of the hierarchical C4 map against the actual codebase.

    SYSTEM_ID: <system-id>
    PREREQUISITE: The codemap/ folder contents have been read. Use that context.

    VERIFICATION GOALS:
    1. Container completeness:
       - Find all deployable units not documented in containers/ folders
       - Verify all databases and services have container folders
       - Check for missing container folders
    2. Component completeness:
       - For each container, find modules not mapped to component folders
       - Check for undocumented major directories
       - Verify component folders exist for all major modules
    3. Code completeness:
       - Find key classes not documented in any code/ folder
       - Check that important design patterns are captured
    4. External system completeness:
       - Find all external integrations not in context diagram

    SEARCH STRATEGY:
    - Glob for: **/package.json, **/requirements.txt, **/Dockerfile, **/docker-compose.yml
    - List all top-level directories under src/ or equivalent
    - Grep for route definitions: "@app.route", "@router", "app.get(", "app.post("
    - Grep for HTTP clients: "requests.", "httpx.", "axios", "fetch("
    - Grep for SDK imports: "import.*azure", "import.*aws", "from stripe"
    - Compare against existing codemap folder structure

    OUTPUT FORMAT:
    Return a completeness report:
    - Missing container folders: [list with evidence]
    - Unmapped component folders: [list with container parent]
    - Missing code documentation: [list with component parent]
    - Missing external systems: [list with import locations]
    - Overall completeness score: X/4 categories complete
```

**Subagent 2: Accuracy Check**
```
Tool: Task
Parameters:
  subagent_type: "Explore"
  description: "Verify C4 accuracy"
  prompt: |
    TASK: Verify ACCURACY of the hierarchical C4 map against the actual codebase.

    SYSTEM_ID: <system-id>
    PREREQUISITE: The codemap/ folder contents have been read. Use that context.

    VERIFICATION GOALS:
    1. Relationship accuracy:
       - For each documented relationship, verify it exists in code
       - Check import statements match component dependencies
       - Verify API calls match container relationships
    2. Technology labels:
       - Verify framework versions match package files
       - Check database types match connection code
       - Validate protocol labels (REST, gRPC, WebSocket)
    3. Hierarchy accuracy:
       - Verify components are in the correct container folder
       - Verify classes are documented under correct component
       - Find misplaced elements in wrong hierarchy level
    4. Naming consistency:
       - Compare folder names with actual module names
       - Flag outdated or incorrect names

    SEARCH STRATEGY:
    - Read import statements in key files to verify relationships
    - Check pyproject.toml/package.json for version numbers
    - Grep for cross-module imports to verify boundaries
    - Compare diagram element names against directory listing
    - List codemap folder names and compare to actual source paths

    OUTPUT FORMAT:
    Return an accuracy report:
    - Incorrect relationships: [list with corrections and evidence]
    - Wrong technology labels: [list with correct values]
    - Hierarchy mismatches: [elements in wrong container/component]
    - Naming inconsistencies: [folder names vs actual names]
    - Overall accuracy score: X% relationships verified
```

**Subagent 3: Hierarchy Validation**
```
Tool: Task
Parameters:
  subagent_type: "Explore"
  description: "Validate C4 hierarchy"
  prompt: |
    TASK: Verify HIERARCHY INTEGRITY of the C4 folder structure.

    SYSTEM_ID: <system-id>
    PREREQUISITE: The codemap/ folder contents have been read. Use that context.

    VERIFICATION GOALS:
    1. Folder structure integrity:
       - Verify expected files exist at each level:
         - System level: context.puml, context.md
         - Container level: container.puml, container.md
         - Component level: component.puml, component.md
         - Code level: classes.puml, classes.md
       - Find orphan folders without required files
       - Find empty containers (no components) that should have components
    2. Cross-level consistency:
       - Containers in context diagram should have matching folders
       - Components in container diagrams should have matching folders
       - Classes in component diagrams should be in code/ folders
    3. Navigation links:
       - All "Parent:" links point to existing files
       - All "Drill Down" links point to existing folders
       - Sibling references are consistent
    4. ID consistency:
       - Folder names (IDs) match PlantUML element IDs
       - IDs are consistent across all diagram levels

    VALIDATION STRATEGY:
    - List all folders in codemap hierarchy
    - Check required files exist in each folder
    - Read markdown files and extract navigation links
    - Verify all links resolve to existing files
    - Extract PlantUML element IDs and cross-reference

    OUTPUT FORMAT:
    Return a hierarchy integrity report:
    - Missing required files: [folder -> missing file]
    - Orphan folders: [folders with no documentation]
    - Broken parent links: [file -> broken link]
    - Broken child links: [file -> broken link]
    - ID mismatches: [folder name vs diagram ID]
    - Overall hierarchy integrity score: X/4 criteria met
```

**Subagent 4: Diagram Quality Check**
```
Tool: Task
Parameters:
  subagent_type: "Explore"
  description: "Validate C4 diagrams"
  prompt: |
    TASK: Verify DIAGRAM QUALITY of the C4 PlantUML files.

    SYSTEM_ID: <system-id>
    PREREQUISITE: The codemap/ folder contents have been read. Use that context.

    VERIFICATION GOALS:
    1. PlantUML syntax in ALL .puml files:
       - Check @startuml/@enduml blocks
       - Verify C4-PlantUML !include statements:
         - Context: !include https://raw.githubusercontent.com/plantuml-stdlib/C4-PlantUML/master/C4_Context.puml
         - Container: !include https://raw.githubusercontent.com/plantuml-stdlib/C4-PlantUML/master/C4_Container.puml
         - Component: !include https://raw.githubusercontent.com/plantuml-stdlib/C4-PlantUML/master/C4_Component.puml
       - Verify correct C4 macros: Person(), System(), System_Ext(), Container(), ContainerDb(), Component(), Rel()
       - Ensure NO Mermaid syntax
    2. Appropriate diagram per level:
       - context.puml uses C4_Context.puml include
       - container.puml uses C4_Container.puml include
       - component.puml uses C4_Component.puml include
       - classes.puml uses standard PlantUML (no C4 include needed)
    3. Coverage balance:
       - No single diagram overloaded (>15 elements)
       - Important components have code-level detail
       - Trivial utilities don't have unnecessary code diagrams
    4. Relationship completeness:
       - All diagram elements have at least one relationship
       - No orphan elements without connections

    VALIDATION STRATEGY:
    - Read each .puml file in the hierarchy
    - Parse @startuml/@enduml blocks
    - Verify !include statements match diagram level
    - Count elements per diagram
    - Check for orphaned elements

    OUTPUT FORMAT:
    Return a diagram quality report:
    - Syntax errors: [file -> error]
    - Wrong include for level: [file -> expected include]
    - Overloaded diagrams: [file -> element count]
    - Orphan elements: [file -> element without relationships]
    - Overall diagram quality score: X/4 criteria met
```

### Step 2: Apply Corrections to Codemap Files

**For missing elements (from Subagent 1):**
1. Create missing container folders: `codemap/<system-id>/containers/<new-container-id>/`
2. Create missing component folders under correct container
3. Create missing code folders under correct component
4. Update parent-level navigation tables

**For accuracy issues (from Subagent 2):**
1. Fix incorrect relationships in .puml files
2. Update technology labels in diagrams and .md files
3. Move misplaced elements to correct hierarchy level
4. Fix naming inconsistencies in folder names and diagrams

**For hierarchy issues (from Subagent 3):**
1. Create missing required files (context.puml, container.md, etc.)
2. Remove or document orphan folders
3. Fix broken navigation links in .md files
4. Align folder names with PlantUML element IDs

**For diagram issues (from Subagent 4):**
1. Fix PlantUML syntax errors
2. Update !include statements to match hierarchy level
3. Split overloaded diagrams into multiple files
4. Add relationships for orphan elements or remove them

### Step 3: Regenerate PNG Exports

After fixing .puml files:

```bash
SYSTEM_ID="<system-id>"

# Regenerate all PNGs
find codemap/$SYSTEM_ID -name "*.puml" -exec plantuml -tpng {} \;
```

### Step 4: Update README

Update `codemap/README.md` with:
- Verification timestamp
- Summary of corrections applied
- Updated folder structure if changed
